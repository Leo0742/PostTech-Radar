# ПочтаТех Радар

Локальный сервис для первичной обработки обращений Service Desk. Он определяет вид обращения, рекомендует линию поддержки, показывает похожие закрытые случаи и строит аналитику по срокам, нагрузке и SLA.

## Что есть в проекте

- очередь новых обращений и ручное подтверждение решения оператором;
- определение вида обращения с оценкой уверенности и TOP-3 вариантов;
- рекомендация линии поддержки;
- поиск похожих обращений с переходом к исходной записи и результату работ;
- база подтверждённых обращений;
- аналитика по длительности, просрочкам, приоритетам, услугам, категориям и линиям;
- отдельная перепроверка сложного случая дообученной Qwen3-Embedding-4B;
- сохранение операторских исправлений без автоматического переобучения рабочей модели.

## Что понадобится

- Python 3.12 или 3.13;
- Node.js 22.12 или новее (вместе с `npm`);
- Git и Git LFS, если проект скачивается командой `git clone`;
- около 15 ГБ свободного места для окружения и базовых весов Qwen;
- интернет во время первой установки.

Основной режим с дообученным MiniLM работает на обычном CPU. Для перепроверки через Qwen желательно 16 ГБ оперативной памяти или видеокарта с достаточным объёмом памяти. На CPU Qwen работает заметно медленнее.

## Вариант 1. Скачать через Git

Этот вариант надёжнее, потому что Git LFS сам скачает крупные дообученные веса.


### macOS или Linux

```bash
cd ~/Downloads
git lfs install
git clone https://github.com/Leo0742/PostTech-Radar.git
cd PostTech-Radar
```

После запуска откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Документация API находится по адресу [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

Остановить сервис можно сочетанием `Ctrl+C` в терминале.

## Что делает установка

Команда `scripts/setup.py`:

1. проверяет наличие наших дообученных файлов;
2. создаёт виртуальное окружение `.venv`;
3. устанавливает Python-зависимости;
4. скачивает с Hugging Face точную ревизию базовой `Qwen/Qwen3-Embedding-4B`;
5. устанавливает frontend-зависимости и собирает React-приложение;
6. создаёт SQLite-базу из `data/raw/Обращения_1931.xlsx`;
7. готовит локальные модели маршрутизации и поиска.

При запуске автоматически выбираются наши финальные файлы:

- дообученный MiniLM и финальная голова категории — для основного анализа;
- Qwen3-Embedding-4B, наш LoRA-адаптер и финальная голова Qwen — для кнопки перепроверки;
- локальные модели — для маршрутизации и поиска похожих обращений.

Веса и их контрольные суммы перечислены в [SUBMISSION_MANIFEST.md](SUBMISSION_MANIFEST.md).

## Быстрый запуск без загрузки Qwen

Если нужно быстро проверить интерфейс и основной сценарий, Qwen можно временно не скачивать:

Windows:

```powershell
py scripts\setup.py --without-qwen
py scripts\run.py
```

macOS/Linux:

```bash
python3 scripts/setup.py --without-qwen
python3 scripts/run.py
```

Категоризация MiniLM, маршрут, поиск и аналитика будут работать. Кнопка перепроверки Qwen станет доступна после обычного запуска `scripts/setup.py`, который докачает базовую модель.

## Как проверить работу

После запуска выполните в другом терминале:

```bash
curl http://127.0.0.1:8000/api/health
```

В ответе должно быть `"status":"ok"`.

Полная автоматическая проверка проекта:

Windows:


macOS/Linux:

```bash

npm test
npm run typecheck
npm run lint
npm run build
```

## Основной сценарий демонстрации

1. Откройте раздел **Обращения**.
2. Введите текст нового обращения или загрузите Excel.
3. Запустите анализ.
4. Проверьте категорию, уверенность, TOP-3 и рекомендацию линии.
5. Откройте похожие обращения и исходные записи.
6. Подтвердите или исправьте решение оператора.
7. Перейдите в **Базу обращений** и найдите сохранённую запись.
8. В **Аналитике** примените фильтры и проверьте сроки, просрочки, нагрузку и риск SLA.

## Данные и модели

Для категоризации и маршрутизации нового обращения используются только поля, доступные при регистрации. Итоговый результат работ, фактическая длительность, просрочка и линия решения не передаются модели как известные признаки нового обращения.

Основной набор содержит 1931 закрытое обращение. Дополнительные 66 примеров из `ALL_TICKETS.xlsx` использовались как train-only материал для адаптации и не попадали в независимую историческую проверку.

4-я линия представлена одним историческим примером, поэтому сервис не выдаёт её как надёжную автоматическую рекомендацию и оставляет решение оператору.

## Структура проекта

- `backend/app` — FastAPI, модели и бизнес-логика;
- `frontend/src` — интерфейс React;
- `data/raw` — исходные Excel-файлы;
- `models/customer_2026-09-21` — финальные дообученные файлы;
- `scripts/setup.py` — первая установка;
- `scripts/run.py` — запуск сервиса;
- `backend/tests` и `frontend/src/*.test.tsx` — автоматические проверки.

## Статус

Версия подготовлена для локальной демонстрации и проверки жюри. Приложение, данные, модельные надстройки, зависимости и команды запуска находятся в одном репозитории. CI/CD для задания не используется.
